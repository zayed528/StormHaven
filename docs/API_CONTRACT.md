# StormHaven API contract

**Owner:** Nandan. **Source of truth:** `backend/app/schemas.py` (frozen at hour 1). The live, always-current OpenAPI docs are at http://localhost:8000/docs when `make api` is running.

The examples below were generated by calling the real API on the synthetic network with AEP labor hours loaded, so they show real shapes and values. If you change `schemas.py`, announce it in team chat and regenerate or update this file in the same PR.

## Rules every consumer can rely on

- **Three separate kinds of answer.** Confirmed facts (`restoration.outage_confirmed`, `restoration.confirmed_etr`) come only from `utility_status` in the request, which stands in for the utility's outage feed. The model never sets them. Model output is tagged `source: "model_estimate"`. Customer actions live in `guidance`.
- **Restoration is always a range** (`p10_hours`, `p50_hours`, `p90_hours`, `range_text`). There is no single promised time.
- **Fallback.** If the location can't be matched, `risk.source` and `restoration.source` are `"fallback"`, `risk.band` is `"Unknown"`, and confidence is `"Low"`. The UI must show the fallback text, not numbers.
- **Privacy.** Every string in a `ConciergeResponse` has been through `core/privacy.scrub_text`, which removes coordinates, internal equipment IDs, phone numbers and emails. Critical-facility locations never appear in any response. `/api/map` returns anonymized premise IDs and coordinates rounded to 4 decimals.
- **Declared needs** (`profile.declared_needs`) are opt-in checkboxes. The backend never infers them.

## Endpoints

| method | path | purpose |
|---|---|---|
| GET | `/api/health` | liveness + which data is loaded (synthetic vs AEP) |
| GET | `/api/map?severity=<0-100>` | Plotly-ready circuit lines + premise points colored by risk band |
| POST | `/api/concierge` | the whole answer for one location: risk + restoration + guidance + alerts |
| POST | `/api/chat` | chat turn; the LLM calls the engines through a tool and explains the results (offline deterministic reply if Bedrock is not configured) |

### POST /api/chat
`history` uses the Bedrock Converse message shape. Scenario and profile defaults are the same as for `/api/concierge`. If the latest user message mentions a downed line, sparking, fire, smoke, shock or a medical emergency, the reply always **starts with a fixed 911 safety message** that is not written by the LLM.

Request:
```json
{
  "history": [
    {
      "role": "user",
      "content": [
        {
          "text": "Will I lose power, and for how long?"
        }
      ]
    }
  ],
  "premise_id": "P-31111",
  "scenario": {
    "severity_percentile": 70
  },
  "profile": {
    "alerts_enrolled": true,
    "channels": [
      "sms"
    ]
  }
}
```
Response (offline mode):
```json
{
  "reply": "Your outage risk is Moderate (Medium confidence). In past storms, the fuse protecting your street was damaged about 8% of the time. If you lose power, most likely 5 hours to 18 hours (best guess about 9 hours). This is an estimate, not a confirmed AEP restoration time."
}
```

## Schemas (field reference)

Enums: `AccessLevel` = ['normal', 'limited', 'blocked']; `DeclaredNeed` = ['medical_device', 'refrigerated_medication', 'mobility', 'infants', 'pets', 'critical_facility', 'works_from_home']; `Channel` = ['sms', 'email', 'push', 'voice'].
`SourceTag` = `model_estimate` | `confirmed` | `fallback`. `TrustInfo.confidence` = `High` | `Medium` | `Low`. `GuidanceItem.phase` = `before` | `during` | `after`.
`AlertsResponse.messages` keys: `pre_storm`, `outage_confirmed`, `estimate_updated`, `restoration_complete`.
