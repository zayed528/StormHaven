# StormHaven API contract

**Owner:** Nandan. **Source of truth:** `backend/app/schemas.py` (frozen at hour 1). The live, always-current OpenAPI docs are at http://localhost:8000/docs when `make api` is running.

The examples below were generated by calling the real API with `STORMHAVEN_DATA=synthetic` (AEP labor hours loaded), so they show real shapes without exposing any AEP IDs. With real data, node IDs look different but the shapes are identical. If you change `schemas.py`, announce it in team chat and regenerate or update this file in the same PR.

## Rules every consumer can rely on

- **Three separate kinds of answer.** In this demo, `restoration.outage_confirmed` and `restoration.confirmed_etr` come only from the explicit simulated `utility_status` toggle; they are not a live AEP feed. The model never sets them. Model output is tagged `source: "model_estimate"`. Customer actions live in `guidance`.
- **Restoration is always a range** (`p10_hours`, `p50_hours`, `p90_hours`, `range_text`). There is no single promised time.
- **Fallback.** If the location can't be matched, `risk.source` and `restoration.source` are `"fallback"`, `risk.band` is `"Unknown"`, and confidence is `"Low"`. The UI must show the fallback text, not numbers.
- **Privacy.** Every string in a `ConciergeResponse` has been through `core/privacy.scrub_text`, which removes coordinates, internal equipment IDs, phone numbers and emails. Critical-facility locations never appear in any response. `/api/map` returns one point per transformer (no home locations) with one premise ID per point.
- **"Estimate updated" message.** Send back `restoration.range_short` from the last answer as `previous_range_text`, and that answer's `scenario` as `previous_scenario`. The message then says old → new with the real reason. With no previous answer for this location, it says "We'll text you if it changes" instead of "changed from X to X". Reset both when the location changes.
- **Map ring.** `map_point_id` is the `/api/map` dot that represents this location, including for a typed premise ID.
- **Declared needs** (`profile.declared_needs`) are opt-in checkboxes. The backend never infers them.

## Endpoints

| method | path | purpose |
|---|---|---|
| GET | `/api/health` | liveness + which data is loaded (synthetic vs AEP) |
| GET | `/api/map?severity=<0-100>` | Plotly-ready circuit lines + premise points colored by risk band |
| POST | `/api/concierge` | the whole answer for one location: risk + restoration + guidance + alerts |
| GET | `/api/weather` | weather context: reference storms (slider labels), damage odds by wind, live 3-day forecast + NWS alerts. **Never changes a number.** |
| POST | `/api/chat` | chat turn; Bedrock selects an answer category and may request one validated what-if; Python renders engine facts (deterministic reply if Bedrock is unavailable or invalid) |

### GET /api/map?severity=60
Truncated. Each circuit is one polyline with `null` separators between segments. **Each point is one transformer** (the homes it serves; `n` = number of homes), never an individual home. `id` is one premise behind that transformer (click → `/api/concierge`); every home behind a transformer shares the same upline path, so it gets the same answer. Coordinates are the transformer's, rounded to 4 decimals. Responses are gzip-compressed (the real-data map is ~6 MB raw, ~1 MB compressed).

### GET /api/weather
Static reference data from `pipelines/07_weather.py` plus a live forecast (Open-Meteo) and active NWS alerts, cached for 30 minutes. On the synthetic network, or with `STORMHAVEN_OFFLINE=1`, or if the services are down, `reference_storms` is empty and/or `forecast.available` is `false`. The UI simply hides the card. Illustrative shape (values made up):
```json

  "reference_storms": [
    {"label": "Mon YYYY", "start": "YYYY-MM-DD", "end": "YYYY-MM-DD", "percentile": 95.8,
     "peak_gust_mph": 56.1, "rain_mm": 93.5, "snow_cm": 0.0}
  ],
  "damage_odds_by_gust": [
    {"gust_from_mph": 0, "gust_to_mph": 30, "days": 1000, "share_with_damage": 0.06},
```

### POST /api/chat
`history` uses the Bedrock Converse message shape. Scenario and profile defaults are the same as for `/api/concierge`. If the latest user message mentions a downed line, sparking, fire, smoke, shock or a medical emergency, the reply always **starts with a fixed 911 safety message** that is not written by the LLM.

History is text-only, must alternate `user`/`assistant`, must end with the latest `user` turn, and is limited to 20 messages, one 1,200-character text block per message, and 12,000 characters total. The full history is structurally validated, but only a best-effort-sanitized copy of the latest user question is sent to Bedrock; client-supplied assistant turns and older messages are excluded. Regex sanitization reduces common PII but is not complete PII detection, so the UI tells customers not to enter names, addresses, account numbers, or medical details.

Bedrock receives a precomputed, allowlisted current outlook. It may request at most one what-if tool call, limited to storm severity, crew availability, or road access values explicitly present in the latest question. Its final output is only a validated answer-category JSON decision; Claude prose and numerical claims are never displayed. Python renders all customer-facing facts directly from the selected deterministic engine response. AWS failures, malformed output, Guardrail intervention, invalid tools, or invalid decisions return the deterministic offline answer.

`utility_status` is accepted for parity with `/api/concierge`, but it represents the explicit demo toggle only. Chat responses label it as a simulation and never claim it came from a live AEP feed.

Request:
```json
{
  "history": [
    {
      "role": "user",
      "content": [
        {
          "text": "Will I lose power, and for how long?"
        }
      ]
    }
  ],
  "premise_id": "P-31111",
  "scenario": {
    "severity_percentile": 70
  },
  "profile": {
    "alerts_enrolled": true,
    "channels": [
      "sms"
    ]
  }
}
```
Response (offline mode):
```json
{
  "reply": "StormHaven's model estimates a Moderate outage risk (25%, High confidence). If you lose power, most likely 5 hours to 18 hours (best guess about 9 hours). Charge phones, laptops, and power banks now. No outage confirmation from a live utility feed is available. This uses the synthetic demo network, not real AEP locations."
}
```
